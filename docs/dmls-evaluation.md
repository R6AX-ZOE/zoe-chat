# DMLS 评估:替代协调者排序的可行性与决策(M4)

> 状态:已评估,维持现状(协调者即 DS)。本文件记录评估过程、依据与再评估触发条件。
> 评估日期:2026-08(对应 DESIGN.md §5.3 的远期选项)。

## 1. 评估对象

| 草案 | 状态(评估时) | 核心思路 |
|---|---|---|
| [draft-kohbrok-mls-dmls-03](https://datatracker.ietf.org/doc/html/draft-kohbrok-mls-dmls) | **已过期**(个人草案,最新 2025-10-20) | 基于 FREEK(Alwen et al.,[ePrint 2023/394](https://eprint.iacr.org/2023/394.pdf))的分叉弹性 CGKA:改造 MLS 密钥调度,允许成员保留密钥材料以**乱序处理 Commit**,用 PPRF(可穿刺 PRF,复用 MLS Secret Tree)缓解前向保密损失;epoch 用字节串而非整数标识;附状态合并(consolidation)流程 |
| [draft-xue-distributed-mls-02](https://datatracker.ietf.org/doc/html/draft-xue-distributed-mls) | **已过期**(个人草案,最新 2025-10-20) | 不同哲学:**不协商单一群组状态**,用多个 MLS 会话的组合保护消息(近似 fan-out / 对偶会话),规避全序问题 |

## 2. 两个草案的本质差异

- **Kohbrok DMLS**:仍维持"所有成员共享一个群组状态",但容忍**分叉**:同一 epoch 出现多个 Commit 时各成员可各自推进;PRF 穿刺保证已删除的 init_secret 无法被重用,从而在乱序处理时尽量保住 FS。分叉最终靠**合并流程**收敛(以 transcript hash 决胜,输侧关闭、赢侧补成员增删)。代价:必须保留旧 ratchet tree 状态(草案自认"damages FS");合并语义依赖较强假设(双方各有服务器协调、无内部攻击者、KeyPackage 可访问),且**多个开放问题未决**(决胜规则、无重叠成员怎么办等)。
- **Xue DMLS**:放弃共享状态。组合多个 MLS 会话(如两两会话/星型会话),消息在多条独立会话上分别加解密。无分叉、无合并,但**群组语义弱化**:成员变更在每条会话上分别传播,规模伸缩与成员资格管理复杂,与 MLS 原生"高效群组增删"优势相抵。

## 3. zoe-chat 需求对照

| 需求 | 现状(协调者即 DS) | Kohbrok DMLS | Xue DMLS |
|---|---|---|---|
| 群组结构变更的可用性 | ⚠️ 协调者离线时受限(已诚实文档化) | ✅ 无单点 | ⚠️ 每条会话独立传播,离线对端仍缺会话 |
| 端到端保密性 | ✅ 协调者零知识 | ✅ | ✅ |
| 前向保密 | ✅ 原生(epoch 推进即轮换) | ⚠️ 为乱序处理保留树状态,FS 有损(草案自认) | ✅ 各会话原生 |
| 实现成本 | 已实现(openmls 0.8.1 封装) | ❌ 需自研密钥调度/PPRF/分叉合并,openmls 无支持 | ❌ 需自研会话组合/资格传播 |
| 规范成熟度 | RFC 9420 | ❌ 草案过期、开放问题未决 | ❌ 草案过期 |
| 协调者故障恢复 | 已有:离线缓冲 + 恢复重放(protocol.md §3) | — | — |

## 4. 结论

**不替换协调者排序**(维持 DESIGN.md Q2 决策),理由:

1. **成熟度不足**:两份草案均已过期且处于个人草案状态;Kohbrok 草案的合并流程仍是 TODO/开放问题,规范未稳定前实现 = 绑定未定语义。
2. **收益与成本不匹配**:zoe-chat 的协调者**只接触密文**(威胁模型里已是零知识);DMLS 解决的是"协调者离线时结构变更冻结"这一**可用性**问题,而它用前向保密损失换取——对本项目不划算。
3. **现有缓解已覆盖主要场景**:普通消息多路径直连不经协调者;结构变更在协调者离线时本地排队、恢复后重放(protocol.md §3);UI 明示冻结状态。
4. **生态约束**:openmls 是锁版本依赖;DMLS 无任何现成实现,自行实现 = 维持整套密码学正确性的长期成本。

**零成本先行改进**(不引入 DMLS,缓解同一痛点):
- 协调者**可轮换**:建群者任第一任;协调者长期离线时,群内其他成员经 Proposal 发起轮换(仍是单协调者模型,但不再是单点宿命)。
- 该改进在现有排序协议内即可实现,列为 M4 后续项。

## 5. 再评估触发条件

满足任一即重开评估:

1. Kohbrok/Xue 草案被 MLS WG **采纳为工作组草案**或发布新修订且开放问题收敛;
2. **开源实现**出现(如 wire / phoenix 或学术实现),经审计可用;
3. 用户场景出现"协调者长期离线且结构变更频繁"的实际痛点(当前按冻结处理,未见)。
4. 社区化运行(DESIGN.md §6.4 远期 DHT 自动发现落地)后,单协调者模型与去中心化定位张力加大。
